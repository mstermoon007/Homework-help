# AI-DEVELOPMENT-RULES — AI 编程"禁止乱跑"机制

> 适用：本项目（Homework Help）内的一切 AI 辅助编码。建立于 P28-01（2026-09-20）。
> 基线依据：`docs/P28/P28-BASELINE.md`（P28-00 最终治理基线）。
> 本文件是强制规范，不是建议。违反任意一条即视为未完成任务，回退修改并重走验证链。

---

## 一、AI 修改原则

任何改动必须沿以下流水线走完，不可跳步、不可倒序、不可并行绕行：

```
问题
  ↓ ① 定义问题（可复现，可断言）
归属层
  ↓ ② 判定问题归属的架构层（KBL / Runtime / POL / GenerationCore / Strategy / Generator / Validator / Presentation / Plugin）
唯一责任模块
  ↓ ③ 找到该层中唯一责任模块（文件名唯一，禁止"顺便多改一个"）
最小修改
  ↓ ④ 只做解决该问题的最小 diff；不动边界外一行
局部验证
  ↓ ⑤ 该模块/所在子系统的针对性验证（npm run verify:* 对应项）
全量验证
  ↓ ⑥ 全链验证（npm test + 全部 verify:* 门禁）+ P28 基线可比对
```
**结束**

### 执行要求

1. **问题可复现**：动手前先写出复现路径（用例/场景/断言），改完用它证明已解决。
2. **归属层唯一**：一个问题只归到一层；跨层问题拆成多个问题逐个处理。
3. **唯一责任模块**：该层内只有 1 个模块对该问题负责；找不到就停下来问，不猜不扩。
4. **最小修改**：diff 仅包含解决该问题的必要行；同文件其他问题另开任务。
5. **局部验证**：先跑模块级验证，再跑全量；全量失败必须回看局部，不跳过、不豁免。
6. **改造成本大于重跑成本**则放弃改动，回退到 ③ 重新定位；不硬改。

## 二、AI 禁止行为

### 禁止 1 — 为了通过测试改变测试标准

不得改动测试的断言、阈值、期望值或删除用例来换取绿灯。
测试标准是契约。契约只能用实现去满足，不能用改契约去满足。

### 禁止 2 — 为了兼容旧代码增加新的兼容层

发现新旧代码不一致时，不得新增 `COMPAT`/`BRIDGE`/适配壳/垫片层。
正确做法：让旧代码走唯一的新路径（迁移），或按归属层拆除旧物。

### 禁止 3 — 发现错误就增加 fallback

不得为报错路径随手加兜底/降级/吞错，掩盖真实故障。
错误要暴露、要归类、要有唯一 handler；静默 fallback 一律视为未修复。

### 禁止 4 — 发现 API 不一致就复制一套 API

不得因"接口对不上"就新造一份同名/近似 API。
唯一责任模块只存在一份；不一致就是那一个模块的 bug，修它。

### 禁止 5 — 发现数据缺失就 AI 自己编数据

数据以 KBL / canonical / 人工维护源为唯一事实源。
AI 不得自造知识点、字段、映射、样例数据填充缺失。缺失就报告缺失。

### 禁止 6 — 发现文档错误直接修改代码

文档与代码不一致时，先用代码验真，再修正文档；禁止为了"文档好看"改动代码行为。

### 禁止 7 — 发现代码复杂就直接重构整个模块

复杂度不是重构理由。复杂度只允许在**解题必需的最小范围内**微调；
整体重构必须拆成独立任务，先立基线（P28-00 全链路 PASS）再重构、重构后全量回归。

### 禁止 8 — 为了 SEO 增加虚假内容

不得为可发现性/排名注入不存在的内容：不伪造评价/评分/学习人数/知识点/页面。
SEO 只允许增强既有真实内容的可读性与结构化（见 P26 红线）。

### 禁止 9 — 为了生成成功降低 Validator 标准

Validator 是题目质量契约。不得放宽语义/难度/结构/查重规则换取生成成功率。
生成失败属于 Generator 侧缺陷，回 ③ 定位。

### 禁止 10 — 为了测试 PASS 删除失败用例

失败用例是资产的验收标准。删用例=删验收。允许且只允许追加用例，不允许删除/跳过/标记 ignore 失败用例。

## 三、验证链（任何改动完成前必须全绿）

| 命令 | 作用 |
| --- | --- |
| `npm run verify` | M0 聚合门禁（5/5） |
| `npm test` | 全链测试 |
| `npm run verify:kbl-dir` / `verify:syntax` / `verify:allow-gen` / `verify:education` / `verify:coverage` / `verify:golden` | 专项门禁 |
| `npm run check:sw-version` / `check-lint` / `check:sitemap` / `check:crawl-health` / `check:llm-understanding` | 工程门禁 |
| `node dev/p28/build-baseline.js` | P28 基线（只读，改动后可重跑比对事实快照） |

规则：局部验证通过 → 全量验证通过 → 才允许收工；任一失败即回到 ① 重新定位。
每次提交前运行 `npm run verify` 与 `npm test`，输出随提交写入 commit message 摘要。

## 四、越界即回退

AI 一旦触犯以上任意一条：
1. 立即停止当前动作；
2. 说明触犯条款与现场证据；
3. 回退本轮改动（git checkout 该批次）重走原则流水线；
4. 记录到 P28 治理留痕（docs/p28/），供复盘。

> 唯一允许偏离的场景：用户 **显式** 指令覆盖某条规则（如"允许删除该失败用例"），且必须留存用户指令作为依据。
