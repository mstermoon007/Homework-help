一句话总纲：在不破坏四层架构、不回退功能的硬约束下，从核心层（知识点库）往外逐层整改：核心层完成题型 SSOT 收敛 + 知识库数据补全 + 知识点库文档的纯粹存放；大服务层完成决策上收 + 难度/螺旋/自适应落地 + 冗余门禁清理；生成层完成旧插件/死代码清理与生成器收敛；UI 层完成快速模式预设 + 知识点对应提醒 + 渲染/控制冗余清理；最后统一执行物理文档整理与移动。每步以「实测核验 → 最小改动 → 门禁回归」闭环推进，可单步回滚。

一、整改目标与硬约束

1.1 目标

  1. 架构不变形：四层归属（UI / 大服务层 / 生成层 / 知识点库）严格以 architecture/layers.json 为唯一权威，任何整改不改变层职责与数据流。
  2. 功能不回退：全部改动经既有门禁（verify:m0-m4、check-regression、check-frozen-core、check-ui-boundary）验证通过方可提交；回归基线快照先行。
  3. 螺旋能力落地：按三维螺旋模型（难度 1-10 / 深度转折 / 自适应预留）补齐知识库字段与策略接线。
  4. 代码净化：清理旧插件、死代码、冗余门禁检测、冗余控制与渲染代码。
  5. 文档物理整理：尤其完成基层知识点库文档的纯粹存放（知识库数据/文档集中、不与 UI/服务/生成文件混放、可守卫）。

1.2 硬约束（物理边界）

shared/ 物理不移动：依据 docs/ARCHITECTURE_LAYERS.md —— common.js 按自身路径注入同目录子模块、预编译 bundle 内嵌 shared/ 模块 id、sw.js 与 dev 门禁与测试均硬编 shared/ 路径。shared/ 为稳定模块根，严禁拆分。知识库代码数据（knowledge-*.js 等）逻辑归 KNOWLEDGE、物理留 shared/，靠 layers.json 分类 + 本文档登记实现「逻辑纯粹」。物理移动只允许发生在 shared/ 之外（根目录散落文件、docs/、archive/、knowledge/、dev/ 临时脚本）。

1.3 整改顺序原则（从核心层往外）

1 核心层
KNOWLEDGE：题型 SSOT、知识库数据补全、知识库文档纯粹存放（基层数据是地基，先稳固）
2 大服务层
SERVICE：决策上收、难度/螺旋/自适应、冗余门禁清理（策略与校验是骨架）
3 生成层
GENERATION：旧插件/死代码清理、生成器收敛（执行引擎纯净）
4 UI 层
DISPLAY：快速模式预设、知识点对应提醒、渲染/控制冗余清理（只发指令只展示）
5 治理
dev + docs/archive/knowledge：门禁矩阵收敛、物理文档整理与移动

可达性判定标准（脚本化核验）：

纪律：旧插件一律「先归档后验证」，验证通过才可从 archive 移除；任何插件清理必须 GEN 授权（Frozen Core）。

六、风险与回滚

风险缓解
误删活跃插件/门禁三重可达性核验 + 一律「先归档不删除」；Frozen Core 授权 + 基线快照
shared/ 物理移动破坏路径注入硬约束：shared/ 物理不移动；知识库纯粹存放走「逻辑登记 + 守卫」而非物理迁移
UI 上收引入回归先上收后删 UI 代码；verify:ui-boundary / practice-page / check-regression 三关
verify:m4 重构（移除迁移检查）遗漏重构后跑全量 verify:m4 + npm test；迁移检查先入 archive 可回滚
文档移动破坏引用只移 shared/ 之外；移动后跑 verify:layers + 相关门禁确认引用不破
知识库补全口径争议补全草案先出（沿用 G1 方法论），评审后应用，每次应用独立 commit

七、AI 编程执行纪律（每步闭环）

  1. 探查 → 约束 → 证据 → 执行 → 验证 → 交付：每步先读目标文件现状，确认改动边界，标注物理文件与层归属，再执行。
  2. 最小改动：一次只改一个主题；不顺手改无关代码；保留未要求改动的内容。
  3. 命令真源：状态以 package.json scripts 与 architecture/layers.json 为唯一权威，不臆造命令。
  4. 先归档不删除：所有清理候选先入 archive/，验证通过后才可从 archive 移除。
  5. Frozen Core 授权：触碰冻结清单（M1 组/M3 组）先 GEN 授权 + 基线快照 + 独立提交。
  6. 独立提交：每阶段一个 commit，可单步 revert。
