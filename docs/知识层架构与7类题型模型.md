# 知识层架构与 7 类题型模型（技术文档补充）

> 配套 [技术文档--基础.md](技术文档--基础.md)；记录 **知识层（Knowledge Layer）** 的结构逻辑，以及 2026-09-09 的「7 类规范题型 / 知识点驱动生成」重构。
> 更新时间：2026-09-09

---

## 1. 定位

知识层是生成引擎的**数据底座**，负责把原始知识点数据归一为规范对象，并通过**单一事实源字典**约束所有枚举（题型、运算、错误、分类、书目、事实）。其产出被策略层、生成层、校验层、渲染层共享。

核心原则：**题型只有 7 类，且由知识点（KP）的 `applicable_question_types` 驱动**；竞赛是模式标签而非独立题型；模块（M0–M13 / C1–C9）仅作为「单元」容器，不再参与题型路由。

## 2. 知识层文件组成

| 文件 | 职责 |
|---|---|
| `shared/knowledge-bank.js` | 知识库入口；按 `年级 → 模块(modules) → 知识点(knowledgePoints)` 组织；`getEntries(subject, grade)` 扁平化输出 |
| `shared/knowledge-math.js` | 数学知识点**数据**（仅数据 + id 引用）；错误定义已外迁到 `ontology-error-map.js` |
| `shared/knowledge-point.js` | 规范化 KP 对象（经 normalizer 归一后对外暴露） |
| `shared/knowledge-ontology-normalizer.js` | 归一：题型→7 类、能力推导、`cognitiveLevel` 等字段校准 |
| `shared/knowledge-ontology-validator.js` | 字段级合法性校验（格式非法=ERROR） |
| `shared/knowledge-ontology.js` | 编排 normalizer/validator，导出 `Ontology.KNOWN_QUESTION_TYPES` 等 |
| `shared/knowledge-operation.js` | 运算数据（操作符、算理） |
| `shared/knowledge-error.js` | 错误数据（仅数据） |
| `shared/knowledge-factual.js` | 事实内容数据 |

### 2.1 归一主流程

`knowledge-ontology-normalizer.fromLegacy(kpRaw)` 是 KP 规范化的唯一入口：
1. 解析 `id`（年级/模块/序列）。
2. `applicable_question_types[].type` 经 `canonQuestionType()` 归一为 7 类规范题型。
3. 由 `schema.QUESTION_TYPE_TO_CAPABILITY` 推导 `capabilities`（能力声明）。
4. 注入 `operations / errors / spiral / structure / context / category` 等规范字段。
5. 经 `knowledge-ontology-validator` 做字段合法性校验。

## 4. 7 类规范题型模型

### 4.1 规范类型（用户侧仅 7 类）

| id | 名称 | category | 吸收的历史题型 |
|---|---|---|---|
| `calc` | 计算题 | calculation | 口算 `oral` |
| `fill` | 填空题 | written | — |
| `choice` | 选择题 | selection | — |
| `judge` | 判断题 | selection | — |
| `geometry` | 操作/作图题 | geometry | 认读 `recognize` |
| `classify` | 分类整理题 | classification | 新增（独立） |
| `apply` | 解决问题/应用题 | application | 开放 `open` |

`competition` 为**模式标签**（落点 `apply`），不单列题型。

### 4.2 别名归一（`CANONICAL_ALIASES`）

- `oral / operate → calc`；`recognize / read / number / count … → geometry`；`open → apply`；`classify / sort / group → classify`；`competition → apply`。
- 归并策略（确定性、可审计）：① 精确匹配 7 类 → ② 显式别名 → ③ 关键字启发式（几何关键字→geometry；其余→calc）。
- `schema.KNOWN_QUESTION_TYPES` 由 `QuestionTypeRegistry.all()` **动态派生**（SSOT，无分叉）。

### 4.3 模式（MODES）

`MODES = ['quick', 'teacher', 'competition']`，对应导航三模式：
- 快速：数学 → 年级 → 册 → 单元 → 题型 → 生成
- 教师：数学 → 年级 → 册 → 单元 → 知识点 → 题型 → 生成
- 竞赛：数学 → 年级 → 题型标签 → 生成

（导航 UI 为 Phase 2；逻辑层已就绪：归一边界 + `MODES` + 生成链路无 moduleId 路由。）

## 5. 生成链路（端到端，知识点驱动）

```
知识库 KB
  └─ knowledge-ontology-normalizer  →  规范 KP（题型/能力已归一为 7 类）
        │
        ▼
策略层 strategy-engine
  · 选题 / 配额 / 双量互锁 / 知识点密度（密度按 kp.category 聚合，moduleId 仅回退）
  · question-type-allocation → 把 KP 分配到 7 类题型
  · comprehensive-strategy → 单元卷编排（按 unitId 过滤；模块仅作单元）
        │
        ▼
生成层 generator-selector
  · 入口即归一 plan.questionTypeId（oral/recognize/open → 7 类）
  · 按 KP 语义 + 能力选最优 Generator；硬阻断防语义错配
  · geometry / classify 为元题型，豁免硬阻断
  · generator-registry：25 个 native core Generator 的 capabilities/questionTypes 在加载时经字典归一
        │
        ▼
校验层 validator/*  →  题型/答案/难度/去重/质量
        │
        ▼
渲染层 presentation/* + svg-*  →  HTML 题卡 / 教学图形
```

**moduleId 在生成链路中的角色**：仅作为 KP 的「单元」归属（`comprehensive-strategy` 的 `unitId` 过滤），不再用于任何题型路由（M7/C3/C8/C9 等分支已移除）。

## 8. 关键不变量（改动时需遵守）

1. 题型枚举只能来自 `question-type-registry.js`；新增题型须同步 schema 能力映射。
2. KB 中不得出现内联错误定义，错误必须经 `ontology-error-map` 的 `ERR_INDEX` 引用（FK 可解析由 `check-ontology-integrity` 守住）。
3. 生成链路不得按 `moduleId` 做题型路由；题型由 KP 的 `applicable_question_types` 决定。
4. 修改 80 个 frozen-core 文件须走 `--baseline` 授权流程。
