题型·知识点映射与能力螺旋上升 · 总体解决方案

四层架构对齐 + 三维螺旋模型版 ｜ 解决「知识点与题型对应不准确」与「题型模块限制『知识点驱动习题生成』能力螺旋上升」 ｜ 2026-09-04
一句话结论：两条病根的本质是「层职责错位」（决策散落 UI 层、题型枚举在知识点库内割裂、校验无语义门槛）。修复后按四层架构收敛：数据在知识点库、决策在大服务层、执行在生成层、展示在 UI 层。而「能力螺旋上升」按三维螺旋模型落地——维度 A：难度控制（1-10 体系，前期主导）；维度 B：深度与接替转折次数（随年级升高、知识点增多而加码）；维度 C：自适应难度（预留暂不开发，正确率提升→难度递增，架构已就绪只待激活）。共 8 个阶段，配一致性门禁分步落地。

零、项目四层架构（权威定义）

「物理稳定 + 逻辑清单」：文件留驻 shared/，逻辑归属以 architecture/layers.json 为唯一权威（npm run verify:layers 校验，未分类即 FAIL）。

UI 层
页面壳 / 交互 / 渲染呈现入口（*.html、feedback/、knowledge/*.html、sw.js）。红线：不决策题目结构；唯一生成入口 PracticeBridge.start（check-ui-boundary 锚定）；不得直调 Strategy/Generator/Plugin.generate。
大服务层
信息传递 / 项目控制 / 外围样式 / 打印等外围控制。典型：practice-bridge.js、strategy/**（含难度、螺旋、自适应）、validator/**、capability-*.js、learner/**、module-catalog.js、*.css。红线：不侵入 Frozen Core 生成算法。
生成层
题目生成核心引擎：题面/答案生成、语义归一、渲染(HTML/SVG)输出（generation-engine.js、generator/**、presentation/**、svg-*.js、plugins/**）。红线：Frozen Core，仅授权 Bug Fix(GEN)；只接受指令生成题目，不承载 UI 决策。
知识点库
基层数据核心：唯一数据来源、schema、规范映射（knowledge-*.js、knowledge-ontology*.js、schemas/*、question-type-registry.js、ontology-*-map.js）。红线：不生成题面、不参与 UI 决策。

注：schemas/knowledge-point.schema.js 在 layers.json 中「生成层/SEMANTIC」与「知识点库」双登记，属既有双归属待治理点，阶段 0 收敛。

一、问题定位：层视角重述两条病根

1.1 病根 A：知识点与题型对应不准确

  • 知识点库内题型枚举割裂：schema KNOWN_QUESTION_TYPES（7 类，含 operate）与 registry TYPES（9 类，含 oral/geometry/recognize）互不一致、无一致性门禁；normalizer 别名 oral/recognize/picture→operate、registry 再 operate→oral，两跳漂移。
  • 知识库数据依赖启发式兜底：574 知识点中 494 个（86%）用非 canonical 题型值，40 个题型值靠关键字启发式（array-closed→geometry 数阵图归几何、pie-chart→calc 扇形统计图归计算），能力决策 614/614 假性全 ALLOW，题型区分度崩塌。
  • UI 越层决策：practice.html 的 QT_STD_MODULES 静态过滤表 + 自实现 kpRatio 分配，属题目结构决策，应在大服务层（question-type-allocation.js 已存在）；越层致「页面过滤」与「生成层能力」脱节（?qt=calc 过滤掉 M1 口算）。
  • 校验无语义门槛：M1-R06 只统计不设 FAIL；无「题型合法性 / 三向一致性」门禁。

1.2 病根 B：题型模块限制螺旋上升

  • 模块被当决策层：出题入口=模块多选，知识点锁死在模块内，无法跨模块按能力组合。
  • 三向关系无单一事实源：页面 QT_STD_MODULES、知识库 moduleId、生成层 capability 三张表手工维护、互不一致。
  • 螺旋建立在地基失真上：题型声明被启发式抹平 → 难度 / 螺旋 / 前置门失真 → 能力无法真正螺旋上升。

二、螺旋上升的三层语义（本次提升的核心）

核心修正：「能力螺旋上升」不是单一维度，而是三个层次逐步展开、共用同一套知识点与题型地基的过程。本方案将螺旋上升明确为三维模型，三层语义与用户三点提升一一对应。
维度 A · 难度控制系统（1-10）—— 螺旋上升的前期载体

用户提升 1：螺旋上升前期表现为难度控制系统（1-10）的难度体系划分。

现状盘点（已实测，体系完备但未用满）：

  • shared/difficulty.js 已有 1-10 结构分档：1-2 单步无括号 / 3-4 两步可连加连减 / 5-6 三步带括号乘除 / 7-8 四步多符号交替 / 9-10 五步以上多层括号；complexityScore 全档严格单调递增，可作深度排序。
  • core.js diffLevel(1-10) / diffScale（难度→数值缩放） / diffMax（难度→推荐最大数）全链路贯通。
  • strategy/difficulty-strategy.js 有效难度 = 静态难度 + 自适应调整，clamp 1-10；strategy/target-difficulty.js 处理用户显式难度。
  • 缺口：知识库 KP 的 difficulty 实际只用到 1-5（全库 574：1→324、2→39、3→81、4→83、5→47，无 6-10）——1-10 标度未用满，前期「难度分级」落地缺「难度标定锚点」。

方案落点：阶段 5A「难度锚点标定」——每年级定义基准难度区间 + 逐知识点把 difficulty 重新标定到 1-10 全标度（知识库层），让「难度分级」成为螺旋上升前期可感知、可验证的第一载体。

维度 B · 深度与接替转折次数 —— 随年级升高、知识点增多而加码

用户提升 2：螺旋上升表现在随着年级升高、知识点增多，要求加深深度和「接替转折次数」。

现状盘点（已有载体）：

  • strategy/spiral-strategy.js 变体档位 S1-S6：prototype→numeric→presentation→context→structure→transfer，已接入 strategy-engine（maxSpiral=6，按 KP 的 spiral_level / max_spiral_level 限幅）。
  • difficulty.js 结构分档的 steps（1→5+）与 alternateOps / nestedBrackets 即「接替转折次数」的量化：1-2 单步、3-4 两步、5-6 三步带括号乘除、7-8 多符号交替、9-10 多层括号。
  • 知识点衔接：prerequisites 前置链（docs/SPIRAL_IMPROVEMENT_PLAN.md P0 螺旋链建模）产生跨知识点「转折」。
  • 缺口：「年级锚点」未建——各年级允许的难度区间 / 螺旋档位 / 步骤上限无权威映射；深度与转折随年级升高的曲线未显式化。

方案落点：阶段 5B「深度与转折」——建年级锚点表（G1-G6 的难度区间、spiral 档、steps 上限），用 complexityScore + spiralLevel + 前置链深度 作为深度度量，随年级升高递增；低年级以维度 A（难度分级）为主，高年级以维度 B（深度/转折）为主。

维度 C · 自适应难度 —— 预留暂不开发（架构已就绪）

用户提升 3：预留暂不开发的：根据学生答题后的水准，自适应知识点难度，且随着正确率提升难度。

现状盘点（策略引擎已实现、默认关闭）：

  • strategy/adaptive-strategy.js（M6-R12..R22）已实现完整自适应规则：R13 有效难度 = 静态/用户难度 + 学习者调整（限幅 ±2）；R14 掌握度→难度（低掌握降、熟练升）；R15 连续正确/连续错误保护；R16 掌握度+置信度+近期正确率→螺旋档；R17 错因→errorFocus；R18 变体选择（基础/数值/呈现/情境/结构/迁移）。
  • learner/learner-model.js 数据完备：mastery（EMA）、confidence、attempts、accuracy、recentAccuracy、recentResults（R26 归一化容错）。
  • strategy-engine 已接线：request.adaptive === true 才激活，默认关闭；当前生成主链（legacy）不传 adaptive → 自适应在线上是「休眠」状态。

方案落点（预留，不开发）：阶段 5C「P-Adaptive 预留」——明确自适应难度为预留能力：不做任何新开发，仅（a）固化预留接口（request.adaptive 开关 + learner 状态 + adaptiveDelta 数据流）；（b）在架构文档登记「预留待激活」；（c）定义后续激活路径与验收（正确率提升→难度递增，R14/R15 已具备）。自适应逻辑本身（adaptive-strategy.js）暂不接入生成链路。

2.4 三维螺旋模型总览（Spiral Cube）

维度语义载体（现状已有）落层随年级/学习者变化状态
A 难度控制1-10 难度体系划分（前期主导）difficulty.js 结构分档、diffLevel/diffScale、difficulty-strategy、target-difficulty大服务层（策略）＋ 知识点库（难度标定）年级升高难度区间上移（G1 1-2 → G6 6-10）体系已有，难度标定待做
B 深度与转折深度加深 + 接替转折次数递增spiral-strategy S1-S6、difficulty steps/alternateOps/nested、prerequisites 前置链大服务层（螺旋/结构）年级升高档位与步骤递增（S1→S6、steps 1→5+）载体已有，年级锚点待建
C 自适应按答题水准自适应难度，正确率提升→难度递增adaptive-strategy R13-R22、learner-model、request.adaptive 开关大服务层（自适应 + 学习者）学习者掌握度/正确率驱动难度与螺旋档实时调整预留暂不开发

四、目标架构：四层主链 + 螺旋三维落层

UI 层
发「科目+年级+题型+题量+难度(1-10)」指令（PracticeBridge.start）；展示规划结果与考试地位；不持有过滤表、不做能力判断、不自实现分配。
大服务层
读知识点库能力 → 规划：题型可见性/分配（question-type-allocation）→ 难度（1-10，difficulty-strategy） → 深度转折（spiral-strategy S1-S6 + structure） → 自适应（adaptive-strategy，预留） → 生成请求派发；批改分发（practice-bridge）。
生成层
按请求（kp + questionType + 难度 + 螺旋档 + 题量）经 generator/** 生成题面/答案并渲染输出；只执行指令。
知识点库
提供知识点数据：canonical 题型声明、五类本体字段、难度标定（1-10 全标度）、螺旋档位（spiral_level/max）、前置链（prerequisites）、考试地位元数据；不生成题面。

螺旋三维落层：难度标定 → 知识点库；难度/螺旋/自适应决策 → 大服务层 strategy；执行 → 生成层；展示 → UI 层。
